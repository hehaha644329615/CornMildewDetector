# 技术细节（Technical Details）

## 1. 最终模型规格

| 项目 | 数值 |
|------|------|
| 框架 | YOLOv8n（Ultralytics） |
| 输入尺寸 | 640 × 640 |
| 类别数 | 2（light_mold / heavy_mold） |
| mAP50 | 0.934 |
| mAP50-95 | 0.653 |
| 模型大小（量化后） | 3.8 MB |
| 推理速度（iPhone 14 Pro） | ≈ 22 FPS |
| 量化方式 | INT8 |

## 2. 类别定义

- **light_mold（轻度霉变）**：仅胚芽端发霉
- **heavy_mold（重度霉变）**：脂肪端已出现发霉迹象

最终方案**不再检测健康类别**。原因见 `PROJECT_STORY.md` 中 v1–v2 的分析：健康样本与轻度霉变视觉高度重叠，且部分标注策略会引入大量背景噪声。

## 3. 霉变率计算公式

$$
\text{霉变率} = \frac{x_1 / 2 + x_2}{5\μ}
$$

其中：

- \(x_1\)：轻度霉变检测数量
- \(x_2\)：重度霉变检测数量
- \(\μ\)：100g 玉米平均粒数（上线版取 120）
- 一斤玉米粒数 ≈ \(5\μ\)

说明：
- 轻度霉变按损失一半重量计算，与饲料厂实际加工逻辑一致（剥离胚芽后只保留脂肪端）
- 分母采用固定预统计均值，避免依赖「检测出所有健康粒」这一不稳定前提

## 4. 训练关键配置（v6）

```python
from ultralytics import YOLO

model = YOLO('yolov8n.pt')
model.train(
    data='data.yaml',
    epochs=50,
    imgsz=640,
    batch=16,
    device=0
)
```

### 数据增强

- 旋转 ±15°
- 水平翻转
- 亮度调整 ±20%

### 训练策略补充

- 先划分 train/val，再分别做增强（避免数据泄露）
- 加入空背景负样本，降低背景虚警
- 所有训练与推理图片均在固定支架、统一距离与角度下采集

## 5. 数据情况（最终版）

| 项目 | 说明 |
|------|------|
| 采集方式 | 固定硬件支架 + 标准木盒 |
| 原始图 | 固定视角下采集 |
| 训练集 | 增强后约 400 张 |
| 验证集 | 与训练集严格隔离 |
| 负样本 | 空背景图增强后约 20 张 |

## 6. 导出与量化

### 导出路径建议

```text
best.pt → ONNX → CoreML（INT8）
```

### 关键点

1. 导出 ONNX 时建议开启 `simplify=True`
2. CoreML 转换时进行 INT8 量化
3. 量化后精度损失极小（mAP 下降通常 < 0.5%）
4. 模型体积从约 12MB 压缩至约 3.8MB
5. iPhone 14 Pro 上推理速度约 22 FPS

## 7. 系统约束

- 必须离线运行（收购现场网络不稳定）
- 模型大小控制在 5MB 以内
- 普通手机实时推理（iOS / 鸿蒙，本项目以 iPhone 14 Pro 演示）
- 输入必须尽量满足「固定距离 + 单层摊平」条件

## 8. 与早期版本的核心差异

| 版本阶段 | 关键变化 |
|----------|----------|
| v1–v2 | Faster R-CNN，3 类，网络图片，健康类别噪声大 |
| v3–v4 | 切到 YOLOv8n，改为 2 类，修复数据泄露，加入背景负样本 |
| v5–v6 | 固定相机采集，数据增强，INT8 量化，最终上线 |

最终性能提升的主要来源不是更复杂的模型，而是：

1. 去掉难以区分的健康类别
2. 硬件标准化锁定输入分布
3. 空背景负样本降低虚警
4. 量化保证端侧可部署
